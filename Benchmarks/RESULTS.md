# 扫描性能记录

测量日期：2026-11-09。设备为 Apple M3 Ultra（Mac15,14），macOS 27.2。基线是本项目提交 `a7649cc`，对照版本是 4.2 开发中的代码；核心代码均以 `swiftc -O` 编译。每次运行新建独立的模拟资源库，测量后仅删除本次生成的样本及其废纸篓项目。

每个样本包含 8,000 个 1 KiB 文件，分布在渲染、代理、优化和分析目录。表内完整扫描和清理各测一次，完整变更令牌为三次中位数；单位为毫秒。结果来自 `ContinuousClock`，覆盖 `ScanLibrary`、`ChangeToken` 和 `CleanupLibrary` 对应的工作；已在系统日志中核对扫描和清理的 `OSSignposter` 区间。

| 磁盘 | 完整扫描：基线 → 当前 | 完整变更令牌：基线 → 当前 | 清理：基线 → 当前 |
| --- | ---: | ---: | ---: |
| 内置 SSD | 22.2 → 21.4 | 18.7 → 3.1 | 98.9 → 47.8 |
| 外置 SSD | 22.3 → 18.8 | 18.2 → 3.1 | 50.8 → 41.8 |
| 外置机械阵列 | 24.4 → 31.4 | 21.1 → 8.1 | 102.8 → 40.2 |

额外的内置盘 100,000 文件样本：完整扫描为 237.0 → 291.3 毫秒，完整变更令牌中位数为 237.5 → 47.7 毫秒，清理为 529.0 → 447.8 毫秒。实时事件缓存复用在发布配置下连续测得 6.19、5.18、5.03 毫秒；它走的是应用缓存路径，不遍历文件，且与完整令牌测量不是同一段代码。

这些是单次或少量、文件较小且可能命中系统缓存的合成样本；没有清除系统缓存，也没有运行真实 Final Cut Pro。机械盘上单库扫描变慢的情况需要结合多个资源库同时扫描时的寻道表现评估，不能把这些数字视为真实项目的性能保证。

`ScannerBenchmark.swift` 只接受已存在的可写目录，并为每次执行创建唯一名称的样本。可以使用 `FCP_BENCH_FILES_PER_DIRECTORY` 改变每类目录的文件数。应用缓存路径的可选测量入口是 `FCP_BENCH_CACHE_VOLUME=/tmp swift test -c release --filter benchmarkLiveCache`；外置卷必须已挂载。清理测试注入“不占用”的进程状态，仅适用于模拟样本。
